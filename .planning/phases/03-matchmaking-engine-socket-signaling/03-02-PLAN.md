# Plan 03-02: Client Socket Integration & Matchmaking Lobby UI

Install `socket.io-client`, configure Vite websocket proxying, create a global `SocketContext` managing the real-time connection and queue state, build an interactive `/lobby` page adhering to `MY_DEFAULT_GUIDELINES.md` and `unslop`, implement the 15-second mutual acceptance modal, and direct users from Dashboard into the lobby.

<task id="03-02-02">
  <action>
    Create `src/context/SocketContext.jsx` with `SocketProvider` and `useSocket()` hook.
    - Connects to Socket.IO with `withCredentials: true` only when user is authenticated (`user !== null` from `useAuth()`).
    - Disconnects socket cleanly when user logs out.
    - Manages state:
      - `isConnected`: boolean
      - `inQueue`: boolean
      - `queueData`: `{ track, difficulty, joinedAt }`
      - `elapsedSeconds`: number (updated via 1-second interval while `inQueue`)
      - `pendingMatch`: `{ matchId, peerDetails, track, difficulty, expiresAt }` | null
      - `matchConfirmed`: `{ roomId, track, difficulty }` | null
    - Event listeners:
      - `match:found` -> sets `pendingMatch`, plays subtle chime / visual trigger
      - `match:confirmed` -> clears `pendingMatch`, sets `matchConfirmed`, redirects to `/room/:roomId`
      - `match:cancelled` -> clears `pendingMatch`, continues search or alerts user
    - Actions exposed:
      - `joinQueue({ track, difficulty })` -> emits `queue:join`
      - `leaveQueue()` -> emits `queue:leave`, resets queue state
      - `acceptMatch(matchId)` -> emits `match:accept`
      - `declineMatch(matchId)` -> emits `match:decline`, resets pendingMatch
      - `createDirectInvite({ track, difficulty })` -> emits `invite:create`, returns promise with room link
  </action>
