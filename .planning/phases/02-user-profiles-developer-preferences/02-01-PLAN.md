# Plan 02-01: Profile Backend API & Schema Extension

## Objective
Extend the Mongoose `User` schema profile subdocument to support developer avatar URLs, bio constraints, and availability preferences, and implement secured REST endpoints (`GET /api/profile`, `PUT /api/profile`) with validation.

---

## Tasks

<task id="02-01-01">
  <action>
    Extend the `profileSchema` in `server/models/User.js` to include:
    - `avatarUrl`: String, trim, default: ""
    - `bio`: String, trim, maxLength: 300, default: ""
    - `availability`: {
        `isSearching`: { type: Boolean, default: true },
        `preferredWindows`: { type: [String], default: ["Weekday Evenings", "Weekends"] }
      }
    Keep existing fields: `targetRoles` ([String]), `skills` ([String]), `timeZone` (String, default: "UTC").
  </action>
  <read_first>
    server/models/User.js
    .planning/phases/02-user-profiles-developer-preferences/02-CONTEXT.md
  </read_first>
  <acceptance_criteria>
    - `server/models/User.js` profileSchema includes `avatarUrl`, `bio` with maxLength 300, and nested `availability` object
    - Default `isSearching` is `true`
    - `node -c server/models/User.js` executes cleanly
  </acceptance_criteria>
  <verify>
    node -e "import('./server/models/User.js').then(m => { const User = m.default || m.User; const paths = Object.keys(User.schema.paths); if (!paths.includes('profile.avatarUrl') || !paths.includes('profile.availability.isSearching')) throw new Error('profile schema missing extended fields'); console.log('Extended profile schema verified'); });"
  </verify>
</task>

<task id="02-01-02">
  <action>
    Create `server/controllers/profileController.js` with controllers:
    - `getProfile`:
      - Route: `GET /api/profile`
      - Retrieves current user via `req.user`
      - Returns 200 `{ success: true, profile: req.user.profile, user: { id: req.user._id, name: req.user.name, email: req.user.email } }`
    - `updateProfile`:
      - Route: `PUT /api/profile`
      - Receives body: `{ bio, targetRoles, skills, timeZone, avatarUrl, availability }`
      - Validates:
        - `bio` length <= 300
        - `avatarUrl` valid URL string format (or empty string)
        - `targetRoles` is an array of strings
        - `skills` is an array of strings
        - `timeZone` is a string
      - Updates `user.profile` fields with sanitized inputs
      - Saves document: `await user.save()`
      - Returns 200 `{ success: true, message: "Profile updated successfully", user: { id: user._id, name: user.name, email: user.email, profile: user.profile } }`
  </action>
  <read_first>
    server/models/User.js
    server/middleware/auth.js
    .planning/phases/02-user-profiles-developer-preferences/02-CONTEXT.md
  </read_first>
  <acceptance_criteria>
    - `server/controllers/profileController.js` exports `getProfile` and `updateProfile`
    - `updateProfile` validates bio length limit of 300 characters
    - Returns updated user payload including extended profile fields
  </acceptance_criteria>
  <verify>
    node -e "import('./server/controllers/profileController.js').then(m => { if (typeof m.getProfile !== 'function' || typeof m.updateProfile !== 'function') throw new Error('profileController missing exports'); console.log('profileController verified'); });"
  </verify>
</task>

<task id="02-01-03">

- All endpoints protected by HTTP-only cookie JWT verification.
