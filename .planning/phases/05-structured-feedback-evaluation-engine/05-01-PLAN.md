# Plan 05-01: Session & Feedback Mongoose Schemas, REST API & Symmetric Reveal Engine

## Objective
Implement MongoDB Mongoose models for `Session` and `Feedback`, build REST API endpoints for submitting peer evaluations with input validation, implement symmetric blind reveal logic, and broadcast real-time submission progress over Socket.IO.

---

## Tasks

<task id="05-01-01">
  <action>
    Create `server/models/Session.js` and `server/models/Feedback.js`.
    - `Session.js`:
      - `roomId`: String, required, unique index
      - `track`: String, default: "Data Structures & Algorithms (DSA)"
      - `difficulty`: String, default: "Mid-Level"
      - `participants`: Array of `{ user: ObjectId ref 'User', role: String ('candidate' | 'interviewer') }`
      - `startedAt`: Date, default: Date.now
      - `endedAt`: Date
      - `status`: String, enum: ['active', 'completed', 'abandoned'], default: 'active'
    - `Feedback.js`:
      - `sessionId`: ObjectId ref 'Session'
      - `roomId`: String, required, index: true
      - `reviewer`: ObjectId ref 'User', required
      - `candidate`: ObjectId ref 'User', required
      - `scores`: {
          `codeCorrectness`: Number (1-5, required),
          `problemSolving`: Number (1-5, required),
          `communication`: Number (1-5, required),
          `architecture`: Number (1-5, required)
        }
      - `strengths`: String, required, minlength: 20
      - `improvements`: String, required, minlength: 20
      - `privateNotes`: String, default: ""
      - `isRevealed`: Boolean, default: false
      - `submittedAt`: Date, default: Date.now
    - Compound index: `{ roomId: 1, reviewer: 1 }` (unique constraint so each reviewer submits once per room).
  </action>

<task id="05-01-02">
  <action>
    Create `server/controllers/feedbackController.js` and `server/routes/feedbackRoutes.js`.
    - `feedbackController.js`:
      1. `getOrCreateSession(req, res)`:
         - Finds or creates a `Session` record by `roomId`. Adds authenticated user as a participant if not present.
      2. `submitFeedback(req, res)`:
         - Validates request body: `roomId`, `candidateId`, `scores` (1-5 for codeCorrectness, problemSolving, communication, architecture), `strengths` (min 20 chars), `improvements` (min 20 chars), `privateNotes`.
         - Ensures reviewer cannot evaluate themselves (`req.user._id !== candidateId`).
         - Saves `Feedback` document.
         - Checks for existing feedbacks in `roomId`:
           - If 2 feedbacks exist, sets `isRevealed: true` on both feedbacks, sets `Session.status = 'completed'`, and triggers Socket.IO event `feedback:unlocked` to `io.to(roomId)`.
           - If 1 feedback exists, triggers Socket.IO event `feedback:submitted` to `socket.to(roomId)` with `{ partnerSubmitted: true }`.
         - Returns `{ success: true, isRevealed, message }`.
      3. `getSessionFeedback(req, res)`:
         - Retrieves feedbacks for `roomId`.
         - If `isRevealed === false`, only returns `{ isRevealed: false, myFeedbackSubmitted: boolean, partnerSubmitted: boolean }` to enforce symmetric blind protection (FEED-02).
         - If `isRevealed === true`, returns the unlocked feedback given to `req.user._id` (with scores, strengths, improvements, and privateNotes) as well as the feedback given by `req.user._id`.
    - `feedbackRoutes.js`:
      - `POST /session/init`: protected
      - `POST /submit`: protected
      - `GET /session/:roomId`: protected
    - Wire into `server/server.js` at `/api/feedback`.
  </action>
  <read_first>

  </read_first>
  <acceptance_criteria>
