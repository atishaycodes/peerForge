# Plan 01-02: Authentication API Endpoints & Auth Middleware

## Objective
Implement secure JWT authentication endpoints (`/api/auth/register`, `/api/auth/login`, `/api/auth/logout`, `/api/auth/me`), manage authentication tokens using HTTP-only cookies (`auth_token`), and create the JWT verification middleware to guard protected routes.

---

## Tasks

<task id="01-02-01">
  <action>
    Create JWT authentication middleware `server/middleware/auth.js` that checks for token validity and attaches the authenticated user to `req.user`.
    - Extract JWT from `req.cookies.auth_token` (primary) or `req.headers.authorization` Bearer token (fallback).
    - If no token is provided, return HTTP 401 `{ message: "Authentication required" }`.
    - Verify token against `process.env.JWT_SECRET`.
    - Query `User.findById(decoded.id).select("-passwordHash")`.
    - If user not found, return HTTP 401 `{ message: "User session invalid" }`.
    - Attach user object to `req.user` and call `next()`.
  </action>

<task id="01-02-02">
  <action>
    Create `server/controllers/authController.js` implementing controller functions for register, login, logout, and getCurrentUser.
    - Helper `sendTokenResponse(user, statusCode, res)`:
      - Signs JWT token with `{ id: user._id }`, `expiresIn: '7d'`.
      - Sets cookie `auth_token` with options:
        `httpOnly: true`,
        `secure: process.env.NODE_ENV === 'production'`,
        `sameSite: 'lax'`,
        `maxAge: 7 * 24 * 60 * 60 * 1000` (7 days).
      - Returns JSON `{ success: true, user: { id: user._id, name: user.name, email: user.email, profile: user.profile } }`.
    - `register`:
      - Validates presence of `name`, `email`, `password` (minimum 6 characters).
      - Checks if email is already registered; if so, returns 400 `{ message: "An account with this email already exists" }`.
      - Hashes password with bcrypt and creates new User with pre-initialized empty `profile` subdocument.
      - Returns `sendTokenResponse(user, 201, res)`.
    - `login`:
      - Validates presence of `email` and `password`.
      - Finds user by email; returns 401 `{ message: "Invalid email or password" }` if not found.
      - Verifies password using `user.comparePassword(password)`; returns 401 `{ message: "Invalid email or password" }` if mismatch.
      - Returns `sendTokenResponse(user, 200, res)`.
    - `logout`:
      - Clears cookie `auth_token` with `{ httpOnly: true, sameSite: 'lax' }`.
      - Returns 200 `{ success: true, message: "Logged out successfully" }`.
    - `getCurrentUser`:
      - Returns 200 `{ success: true, user: req.user }`.
  </action>
  <read_first>
    server/models/User.js
    .planning/phases/01-backend-foundation-authentication/01-CONTEXT.md
  </read_first>
  <acceptance_criteria>
    - `server/controllers/authController.js` exports `register`, `login`, `logout`, and `getCurrentUser`
    - Cookie is set with `httpOnly: true` and `sameSite: 'lax'`
    - Registration validates inputs and hashes password
    - Login validates password with `comparePassword`
  </acceptance_criteria>

  </verify>
</task>
